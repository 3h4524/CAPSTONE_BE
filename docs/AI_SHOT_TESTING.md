# Manual verification: AI scene video generation

AI Scene Video uses the system-owned `MiniMax__ApiKey` to call the full `MiniMax-H3` model at 768P through the official V2 API. Sellers do not connect their own MiniMax key. MiniMax lists the 768P output price as US$0.08 per generated second, and the app asks for confirmation before each set of new clips. The selected provider, model, resolution and price are captured in every new scene snapshot; old Veo snapshots continue to resolve to their original Gemini/Veo strategy and Seller Gemini key. A storyboard can contain one to four AI scenes with a combined duration up to 30 seconds. Existing clips are reused only when the scene's source, compiled prompt and generation settings fingerprint match. Standard scenes remain supported as a separate mode; mixing Standard and AI in one storyboard is deferred.

Every compiled AI scene prompt ends with mandatory product-identity, source and template constraints. Persisted template prompts can add direction but cannot remove the required constraint. The common constraint preserves product construction, color, artwork placement, visible spelling and logo identity; template constraints then allow only the physical changes appropriate to Showcase, Macro, Lifestyle, UGC, Story or Reveal scenes. New Macro Detail scenes default to a locked camera because generative camera motion can redraw fine artwork. Prompt constraints reduce drift but do not make generative video pixel-exact; use deterministic image motion when exact artwork reproduction is required.

## One-time setup

1. Apply the normal database-first [`scripts/sql/video-workflows.sql`](../scripts/sql/video-workflows.sql) update to the development database after checking the target connection. It seeds the six AI prompt definitions into `video_templates.effects_config`; no EF migration is used.
2. Make sure Redis and the database are running. Add a pay-as-you-go MiniMax key to the backend's ignored `.env` as `MiniMax__ApiKey=...`, then restart the API. Gemini remains a separate Seller connection for listing content, historical Veo jobs and optional generated keyframes.
3. Rebuild and restart the backend API from this branch. A previously running API process still serves the old code. If using `Start-VideoDev.ps1`, first build the Release API and ensure port 5191 is free; the script checks ports and will not stop existing processes.
4. Start the media worker with `./scripts/Start-MediaWorker.ps1` in a separate PowerShell terminal. It uses the worker key from `.env`. Restart the frontend from this branch too.

## UI test

1. In Generate Video, select **AI Scene Video**. Start with one 4-second **Cinematic Product Showcase** scene; an approved product-only Hero mockup is enough. Advanced scene controls are temporarily disabled while the versioned templates and P1 rules are evaluated.
2. For **Macro Detail Reveal**, any current approved product image or approved studio keyframe can be selected regardless of its mockup role. A marked artwork/detail region at least 512 pixels on its shortest side is cropped automatically when available; otherwise the full selected image is used, so a close-up keyframe gives the clearest detail. For person templates, choose an approved image that already contains the person and confirm usage rights. A person is never invented from a blank product mockup.
3. Preview the storyboard. AI scenes show their source image and planned settings, not fabricated motion. The actual clip appears only after generation.
4. At Mockup Approval, approve the current source images and click **Continue with approved mockups**. Review the MiniMax model, resolution and total provider estimate before confirming. This is the point after which paid H3 requests may be submitted.
5. Wait for the Generate Video job. The worker processes scenes sequentially by default, downloads MiniMax's temporary result URL immediately, stores generated clips privately, composites the final silent MP4, and runs technical QA. `AI_SCENE_CONCURRENCY` can raise the limit after the system MiniMax account has been verified with concurrent generations. Review each generated scene and product details before approving/exporting.

If a job fails, inspect `artifacts/video-dev/worker-error.log` when using `Start-VideoDev.ps1`, or the terminal running `Start-MediaWorker.ps1`. When a provider answers without a clip, the run shows the reason it gave. **Retry checkpoint** reuses already stored clips, resumes the exact provider task recorded in each snapshot and, after a new cost confirmation, submits again only missing scenes using the current canvas settings. A submission with an uncertain outcome is never automatically sent again. **Regenerate AI clips** explicitly requests fresh clips and shows a new cost confirmation; check provider usage first if a previous submission may have succeeded. Do not delete or recreate the batch merely to retry the video checkpoint.

## Local no-charge verification

From `media-worker`, run `npm.cmd run check`, `npm.cmd test`, and `npm.cmd run smoke:ai`. The AI smoke command generates a synthetic clip locally and verifies the real Remotion/FFmpeg path without calling MiniMax. Unit tests mock task creation, polling, refusal handling, temporary URL download and old Veo routing. A paid H3 request still requires an explicitly budgeted manual test with a real MiniMax key.

## Review quality and RAG lessons

MiniMax H3 is fixed for this evaluation stage. Review findings are never categorised as a model fault or used to suggest changing model. After a scene is generated, use **Evaluate scene** from Review Video to run the locally configured PaddleOCR and VBench adapters on the stored clip and its approved source image. The status is saved as `queued`, `running`, `completed`, `uncertain`, `skipped`, or `failed`. Missing Python, VBench, PaddleOCR, or GPU produces `skipped`, `uncertain`, or `failed` evidence and never blocks video approval, download, or export.

The repository provides the adapter entry points and local setup in [`tools/video-quality/README.md`](../tools/video-quality/README.md). Keep `VideoQuality:Enabled` false until PaddleOCR, VBench, and their local dependencies are ready; enabling it does not create or bill a MiniMax clip.

Record the start/end time, issue type, severity, whether the issue already exists in the source image, and a concise observation. The application suggests `source_image`, `prompt_template`, `prompt_rule`, `rag_experience`, or `unknown`; the seller confirms or overrides it. An issue in the source image does not become a lesson. `unknown` remains an observation until comparable scenes provide enough evidence to classify it.

Only a confirmed review can create a private candidate lesson. Review the candidate text and select **Verify** before it can affect a future prompt. Editing it creates a new candidate revision and retires the previous revision; it never overwrites the original lesson. Rejecting or retiring the lesson removes it from future retrieval immediately. The system retrieves at most three verified owner-scoped lessons and at most 1,500 characters, then displays them as a separate **RAG experience** section in Prompt Preview. Continuing from that preview binds its storyboard fingerprint to the quote; confirmation writes the signed prompt snapshot for rendering. A changed prompt or source revision requires another preview and quote. Each scene snapshot keeps the compiled prompt, MiniMax H3, source revision, template/rule versions, and lesson IDs/revisions used to create the clip.

Use one seller-controlled real H3 clip when checking an implemented change. Do not create a paid A/B/C batch or a fixed clip count. Compare only videos with a sufficiently similar source image, brief, template, and scene configuration.
