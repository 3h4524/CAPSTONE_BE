# Manual verification: AI scene video generation

For temporary flow testing, AI Scene Video uses the active Gemini API key connected in Provider Settings to call `veo-3.1-lite-generate-preview` at 720p. The key must have paid Veo access; successful image generation alone does not prove Veo access. Google's listed Lite price is US$0.05 per generated second, and the app asks for confirmation before each set of new clips. The selected model and price are centralized in `Application/Features/Workflows/AiVideoModel.cs`; change them there when returning to Fast after the flow test. A storyboard can contain one to four AI scenes with a combined duration up to 30 seconds. Existing clips are reused only when the scene's source and compiled-prompt fingerprint match. Standard scenes remain supported as a separate mode; mixing Standard and AI in one storyboard is deferred.

Every compiled AI scene prompt ends with mandatory product-identity, source and template constraints. Persisted template prompts can add direction but cannot remove the required constraint. The common constraint preserves product construction, color, artwork placement, visible spelling and logo identity; template constraints then allow only the physical changes appropriate to Showcase, Macro, Lifestyle, UGC, Story or Reveal scenes. New Macro Detail scenes default to a locked camera because generative camera motion can redraw fine artwork. Prompt constraints reduce drift but do not make generative video pixel-exact; use deterministic image motion when exact artwork reproduction is required.

## One-time setup

1. Apply the normal database-first [`scripts/sql/video-workflows.sql`](../scripts/sql/video-workflows.sql) update to the development database after checking the target connection. It seeds the six AI prompt definitions into `video_templates.effects_config`; no EF migration is used.
2. Make sure Redis and the database are running and the existing Gemini key shows Connected. Veo needs billing enabled in the Google project linked to that key.
3. Rebuild and restart the backend API from this branch. A previously running API process still serves the old code. If using `Start-VideoDev.ps1`, first build the Release API and ensure port 5191 is free; the script checks ports and will not stop existing processes.
4. Start the media worker with `./scripts/Start-MediaWorker.ps1` in a separate PowerShell terminal. It uses the worker key from `.env`. Restart the frontend from this branch too.

## UI test

1. In Generate Video, select **AI Scene Video**. Start with one 4-second **Cinematic Product Showcase** scene; an approved product-only Hero mockup is enough. Expand the advanced scene settings to inspect camera, movement and lighting options, then add other scenes/templates as desired.
2. For **Macro Detail Reveal**, any current approved product image or approved studio keyframe can be selected regardless of its mockup role. A marked artwork/detail region at least 512 pixels on its shortest side is cropped automatically when available; otherwise the full selected image is used, so a close-up keyframe gives the clearest detail. For person templates, choose an approved image that already contains the person and confirm usage rights. A person is never invented from a blank product mockup.
3. Preview the storyboard. AI scenes show their source image and planned settings, not fabricated motion. The actual clip appears only after generation.
4. At Mockup Approval, approve the current source images and click **Continue with approved mockups**. Review the total Google cost estimate before confirming. This is the point after which paid Veo requests may be submitted.
5. Wait for the Generate Video job. The worker processes scenes sequentially by default, stores generated clips privately, composites the final silent MP4, and runs technical QA. `AI_SCENE_CONCURRENCY` can raise the limit after the connected Google project has been verified with concurrent generations. Review each generated scene and product details before approving/exporting.

If a job fails, inspect `artifacts/video-dev/worker-error.log` when using `Start-VideoDev.ps1`, or the terminal running `Start-MediaWorker.ps1`. When Google answered without a clip, the run shows the reason it gave. **Retry checkpoint** reuses already stored clips, resumes known Veo operations and, after a new cost confirmation, submits again only missing scenes using the current canvas settings. A clip Google drops while stating that the attempt was not charged is submitted once more by itself. A submission with an uncertain outcome is never automatically sent again. **Regenerate AI clips** explicitly requests fresh clips and shows a new cost confirmation; check Google usage first if a previous submission may have succeeded. Do not delete or recreate the batch merely to retry the video checkpoint.

## Local no-charge verification

From `media-worker`, run `npm.cmd run check`, `npm.cmd test`, and `npm.cmd run smoke:ai`. The AI smoke command generates a synthetic clip locally and verifies the real Remotion/FFmpeg path without calling Google. The paid Veo request itself requires a manual test with a billed key and cannot be validated by these checks.
